ESKF declared-rest startup comparison, 7 October 2026
===================================================

The new independent at-rest velocity constraint substantially reduces the
GPS-denied startup failure. ESKF still does not beat native EKF2/EKF3 across
all tested conditions or metrics. The geometry options still have tradeoffs
and remain disabled by default. This is progress toward the objective, not
a completed estimator selection or flight qualification.

Browse eskf-stationary.html for the explicit-rest baseline against native
EKF2/EKF3, eskf-stationary-alignment.html for conditioned alignment, and
eskf-stationary-vector.html for alignment plus symmetric magnetic-vector
fusion. Each chart shows three-seed median and range, with all GPS, denial,
loss/return, rate, delay and scoring-window combinations. Sibling CSVs retain
per-seed results. eskf-stationary-ablations.csv joins all five evidence stages,
including the previous baseline, for 4320 per-seed/window rows.

Experiment and implementation
-----------------------------

Original motion is .6 rad/s, seeds 7/19/41; held-out motion is .85 rad/s,
seeds 101/307/911. Both 100/50/50 Hz and 25/25/25 Hz flow/mag/baro profiles
use the same 800 Hz IMU, 10 Hz GPS and 100 Hz scoring epochs. GPS loss uses
measurement timestamps 25 <= t < 40 s. Flight scores cover 13 <= t < 60 s.
Zero/nominal/stress arrival profiles and the native source pins, original
packet timestamps, fixed-delay rules and output interpolation are unchanged
from native-delay.txt. The exact same 216 native runs are reused, not rerun.
Every new ESKF delivery count and payload digest equals the corresponding
native transport trace. Capture hashes equal the previous ESKF evidence.

The original comparison supplied native at-rest/armed information through
13 s but supplied no explicit ESKF rest input. The new vehicleAtRest input
states physical rest. It defaults false and is not inferred from IMU magnitude
or disarmed status. With the input asserted, a separate velocity constraint
with per-axis variance .01 m2/s2 fuses alongside real aiding. This fixed .1 m/s
standard deviation is an explicit soft-constraint choice, not a sensor noise
estimate or a variance tuned separately for each seed. Initial states,
process noise and sensor covariances are unchanged. No truth position, attitude,
velocity or IMU bias is provided to the filter.

The correction uses the existing local SE_2(3) body-tangent residual -R'v,
block velocity observation matrix and Joseph covariance update. It is a
compact reuse of existing geometry, not a new full bias-aware equivariant
filter. Independent stationary acceptance leaves a rejected GPS anchor's
health counters intact. Accepted corrections notify the output predictor
once per fusion instant, including when rest is the only accepted constraint.
The old quiet-IMU/unaided fallback remains separate.

The buffered scheduler evaluates the rest phase at the released filter IMU
timestamp, not the current output timestamp. The filter therefore still uses
rest information for pre-takeoff states during the first .2 s of current
flight output. This is required for the same time interpretation as all other
horizon measurements. A generated-component regression exercises this boundary
and release, and checks the correction count used for forward rebasing.

The ESKF block accepts the input through an instance modifier, for example
Estimator(vehicleAtRest=landedAndStationary). The composed HorizonEstimator
currently does not expose a stationary-phase queue. Its Rumoca 0.10.2 export
still fails at HorizonEstimator.mo:259:5 on filterPositionHeld_m assignment;
the added declarations shift diagnostic identity 575 to 577. The CI boundary
was updated only after reproducing the same clock-ownership diagnostic.
The comparison uses explicitly scheduled generated components and keeps the
previous horizon implementation and host-only scheduling limits.

The original denied retrodiction failure is greatly reduced by explicit rest.
The improvement is smaller on the held-out set; native PX4 remains clearly
ahead in denied position, velocity and yaw. In original high-rate denial,
the rest horizon has lower horizontal error than EKF3, but worse yaw. On the
held-out denied set, EKF3 still has lower horizontal error than this horizon.
Vector fusion improves return/outage scores but worsens original denied
horizontal error. Alignment alone does not consistently improve this matched
startup comparison. Selecting the best option separately for each case would
hide these tradeoffs; no such selection or default change is made here.

GPS return smoothness
---------------------

Native stacks use output observers; the ESKF horizon reapplies buffered
increments with an exact correction rebase. Small state RMSE does not imply
small correction jumps. These are median maximum consecutive 3D
position-error jumps over 39 <= t < 45 s (m), covering one second before and
five seconds after GPS returns. These are not raw position increments. GPS source-active and accepted-fusion flags have different
meanings across stacks and are not used to rank reacquisition latency.

Covariance and validation
-------------------------

Thirty-six additional retrodiction replays check the full 15x15 covariance
through nominal-delay denied flight for all three rest/geometry options,
both rates, all seeds and both motion sets. Every covariance row is symmetric
and admits a positive Cholesky factor. Diagnostics do not alter the state
output hash relative to the corresponding primary replay. Bias truth is used
only in the offline local-error/NEES calculation. The table reports medians
of per-seed mean 15D NEES for flight, not independent Monte Carlo samples:
  original base      100/50/50 Hz   4.4320
  original base      25/25/25 Hz    3.1665
  original alignment 100/50/50 Hz   4.5183
  original alignment 25/25/25 Hz    3.1215
  original vector    100/50/50 Hz   6.2723
  original vector    25/25/25 Hz    4.1388
  held-out base      100/50/50 Hz   3.6597
  held-out base      25/25/25 Hz    3.0977
  held-out alignment 100/50/50 Hz   3.6111
  held-out alignment 25/25/25 Hz    3.1192
  held-out vector    100/50/50 Hz   4.4550
  held-out vector    25/25/25 Hz    4.3756

These low aggregate NEES values do not establish calibration of every state
or every scenario; dimension-specific ratios and bias errors remain in the
JSON. Horizon/output and native covariance consistency are still unavailable.

The independent generated-C aiding fixture checks rest alongside GPS, flow,
barometer and magnetometer, GPS outlier health, rest release, quiet IMU without
rest, stationary-only correction notification, duplicate IMU refusal, positive
covariance, and disabled/negative/nonfinite variance behavior across geometry
modes. The horizon fixture checks preserved fixed sensor covariance and rest
at the delayed fusion epoch. Nonfinite configuration may signal a generated
runtime error; it never accepts the stationary correction. OpenModelica
simulations of StationaryAidingTests and MultisensorAidingTests pass; the new
stationary model is balanced at 843 equations and variables. Tests.All lowers
to canonical DAE under Rumoca 0.10.2. Seven Python scoring tests, package
structure, formatting and diff checks pass. Three interactive reports each
pass 576 filter/metric selections. All 216 default-off delayed replay outputs
are byte-identical to the preceding stage. No full mission suite, remote CI,
fresh native-core rebuild, native timing comparison or flight-target
qualification was run in this stage. Source history remains uncommitted.

Remaining gaps and next experiments
-----------------------------------

The rest constraint fixes an information mismatch and a startup weakness;
it does not explain all PX4/EKF3 advantages. Priorities are now bias-aware
propagation/observation consistency under a complete Lie-group error model,
magnetic tilt/bias coupling and robustness, and current-output observer
tradeoffs. A future geometric variant must transform bias action, process
noise, measurement Jacobians, covariance reset and delayed forward prediction
consistently, rather than changing only the retraction. Check motion and
sensor-disturbance cases beyond these smooth fixed-field captures before
making a general flight-performance claim. Retrodiction versus horizon needs
flight-target CPU/RAM evidence as well as the host timings already retained.

Reproduction
------------

Use a new project-specific directory under $HOME/scratch for build outputs and
fresh evidence. Build with tools/estimator_comparison/build.py --eskf-only
--horizon and pinned Rumoca 0.10.2. Run compare_delay.py with
--stationary-until 13 --repetitions 1; all three delay profiles are included by
default. Original data uses --frequencies .6 --seeds 7 19 41; held-out uses
--frequencies .85 --seeds 101 307 911. Repeat a fresh build with
--geometric-alignment, then with that option and --equivariant-magnetometer.
No capture regeneration or parameter sweep is needed for this stage.

For the 36 covariance cases, run evaluate.py on each retrodiction binary and
data set with --scenarios denied --diagnostics --delay-profile nominal
--stationary-until 13 --gyro-bias .0008 -.0005 .0004
--accel-bias .02 -.01 .015 and the same frequencies/seeds.

report_native_delay.py --directory EVIDENCE --output EVIDENCE/eskf-stationary.html
--eskf-prefix eskf-stationary renders the primary comparison. Use
--eskf-prefix eskf-stationary-alignment or eskf-stationary-vector and
--review-prefix eskf-stationary for the two geometric reports. Native evidence
files remain native-delay-{original,held-out}.json, with their original
manifest. eskf-stationary-manifest.json records current source/input/binary and
artifact hashes, validation coverage and the still-unachieved objective.
