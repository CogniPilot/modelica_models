Formal contracts and implementation comparison — 7 October 2026

The goal is better estimation, supported by specific mathematical and numerical
evidence. No checked result orders ESKF, EKF2 and EKF3 for every flight and noise
realization. Equality of correctly modeled linear Kalman updates already rules
out a claim of strict superiority everywhere. Lower deterministic truncation
error, numerical covariance validity and lower empirical RMS are distinct claims.

Implementation comparison
-------------------------

CogniPilot ESKF
  State: SE_2(3) pose/velocity and additive gyro/accelerometer biases; 16 nominal
  components, 15 local right-error covariance coordinates. Auxiliary terrain and
  pressure datum have their own logic; they are not a fully joint magnetic/wind/
  terrain state. Optional semidirect bias geometry is a separately tested branch,
  not an assumption that biased INS has globally linear logarithmic error.
  Integration: the ACC paper's retained FOH Magnus mean and first-order bias-
  Jacobian correction, with approximate held-equivalent Simpson process noise.
  It is not exact integration for arbitrary changing IMU inputs. Deterministic
  truncation, finite bias-change remainder and shared endpoint correlation remain;
  matching the retained mean/Jacobians does not establish exact covariance.
  Aiding: geometric alignment, optional endpoint-averaged vector magnetic update,
  exposure-aware optical flow, pressure altitude, GPS and timestamp checks.
  Delays: both retrodiction and buffered 200 ms fusion horizon plus forward output
  prediction are replayed on identical captures. Publication-state RMS is distinct
  from covariance consistency at the horizon epoch.
  Numerics: dense generalized Joseph correction and opt-in QR square root. The
  new conditional-noise guard validates joint state/measurement covariance.

PX4 EKF2 native baseline
  Audited source: f1c0a1f794edf8e5e974b6ed96df3f95eda0df39. Its generated state
  header has 25 nominal components / 24 error coordinates: attitude, velocity,
  position, gyro/accelerometer bias, earth/body magnetic fields, horizontal wind
  and terrain. This is already an attitude error-state EKF; do not describe it as
  a naive additive quaternion filter. Its Lie-compatible rotation alone cannot
  be an ESKF novelty or evidence of superiority.
  Aiding uses native source selection, magnetic/height modes, checks and resets.
  Buffered delayed fusion plus output prediction matches the broad architecture
  of the ESKF horizon mode. Exact models, epochs, tuning and scheduling still differ.
  Official overview: https://docs.px4.io/v1.17/en/advanced_config/tuning_the_ecl_ekf

ArduPilot EKF3 native baseline
  Audited source: 1511f27194f1dcc3728270883047bdf022b3fd53 (Copter-4.7.0).
  AP_NavEKF3_core.h defines 24 states including four quaternion components,
  velocity, position, delta-angle/delta-velocity IMU bias, earth/body magnetic
  fields and horizontal wind. Terrain/range has separate handling. Quaternion
  normalization and its native covariance equations must be respected in parity.
  It uses delayed fusion, output propagation, source sets, validity/flight-phase
  decisions and resets. At 2 m this replay selects heading-only magnetic fusion;
  at 4 m it naturally enters three-axis fusion. This policy difference is not a
  failure of EKF3 and cannot be erased by relabeling its output as a common filter.
  Native range delay/median filtering remains different from the delivered flow
  midpoint range. Accepted fusion epochs require instrumentation, not inference
  from the sensor CSV's timestamp or replay adapter call count.
  Official overview:
  https://ardupilot.org/copter/docs/common-apm-navigation-extended-kalman-filter-overview.html

Neither native architecture is represented completely by the external Modelica
ports. Latest stable release kernel parity is separate: PX4 v1.17.0 and Copter-
4.7.1 in release-port-refresh.txt. The flight scores above use older native pins.
Prediction/GPS kernel bit equality does not establish full optical-flow, magnetic,
height or source-switching parity. No upstream code is copied into this repository.
The release PX4 float32 kernel audit matched 191,040 components across 320 cases;
the release EKF3 float32 audit matched 96,560 components across 160 cases. Those
are compiled kernel facades, not complete firmware parity. ArduPilot's default
double-precision SITL build is also distinct from a float32 deployment comparison.
Release references:
https://github.com/PX4/PX4-Autopilot/releases/tag/v1.17.0
https://github.com/ArduPilot/ardupilot/releases/tag/Copter-4.7.1

---------------------

Author/committer and DCO: James Goppert <james.goppert@gmail.com>.
The canonical checkout's uncommitted work was preserved. New proofs were prepared
in an owned clone; gnc-estimation-covariance.patch is the durable reviewable change.
That commit has not been pushed. The current environment cannot write canonical
GNC/main Git metadata or scratch storage. It cannot resolve GitHub for Git pushes.

1. KalmanCorrection.generalized_joseph
   Hypotheses: finite-dimensional real matrices, symmetric prior P, measurement
   H e+v, C=Cov(e,v). Arbitrary K is allowed. Proves the expanded correlated
   Joseph covariance identity. Matches correctLinear's cross terms and constrained
   gains; not a proof that the supplied C reflects the physical sensor process.

2. KalmanCorrection.gain_gap / gain_gap_positive_semidefinite
   Hypotheses: symmetric/PSD S and Kopt S=P H^T+C. Proves the covariance gap equals
   (K-Kopt) S (K-Kopt)^T and is PSD. This establishes modeled linear optimality,
   shared by equally modeled Kalman filters; no nonlinear MSE or stack ranking.

3. KalmanCorrection.conditional_factor_identity /
   conditional_factor_positive_semidefinite
   Hypotheses: P=L L^T, C=L U, R=U^T U+V V^T. Posterior is A A^T+(K V)(K V)^T,
   where A=(I-KH)L-K U^T. It is PSD for arbitrary K. This motivates the dense
   joint-covariance check and existing square-root update. Actual float32 code
   is challenged independently; Lean has not verified the factorization routine,
   floating-point rounding, Modelica compiler or C compiler.

4. KalmanCorrection.impossible_scalar_joint
   P=H=R=1, C=2 yields positive innovation S=6 but posterior -1/2. This refutes
   positive innovation alone as a sufficient validity check. Generated-C tests
   reproduce the old dense failure and require rejection with prior preservation.

5. InertialAidingObservability.horizontal_translation_unobservable /
   prediction_preserves_translation / gps_observes_translation
   Hypotheses for physical use: positive range over known flat ground, constant
   local magnetic field/gravity, position-independent inertial dynamics. A common
   horizontal translation leaves optical flow, range and magnetometer output
   unchanged; inertial position propagation preserves that translation, GPS sees
   it. Initial priors can anchor an estimate; these sensors cannot recover a new
   absolute horizontal datum. Excludes mapped terrain, landmarks and field maps.
   Does not prove the implementation preserves the unobservable covariance mode.

6. BearingOutput.averaged_cubic_bound / averaged_le_embedded
   Hypotheses: the defined unit bearing geometry, rotation angle 0<=theta<=pi.
   Endpoint averaging gives deterministic residual norm <=theta^3/12 versus
   the ordinary embedded residual. This supports the geometric magnetic design.
   BearingOutput.averaged_noise_term explicitly retains the extra noise/error
   coupling. A better deterministic bound does not prove smaller stochastic MSE.

7. BearingComparison.retraction_eq_eqf_star / retraction_cubic_bound
   A suitable retraction EKF has the SAME residual as the equivariant construction
   in this geometry. Thus a blanket claim that all EKFs have only quadratic
   residuals while ESKF is cubic would be false. No verified identification of
   every PX4/AP magnetic mode with one of these idealized residuals is supplied.

8. CovariancePropagation.coordinate_equivalence /
   same_sensitivity_same_covariance; NoiseCoordinates.noise_factor_congruence
   Matched first-order sensitivities and correctly transformed noise give the same
   physical covariance. Scaling a residual by s also scales its R by s^2; leaving
   R fixed creates an apparent information gain, not a geometry improvement.

9. GroupAffine.group_affine_on_right_error_derivative; InertialBias results
   State-independent group error requires the group-affine hypothesis. Biased
   inertial dynamics retain finite-error bias-coordinate nonlinear terms, with
   aligned/perpendicular examples. Current 15D ESKF is not thereby globally
   log-linear, globally convergent or immune to unobservable sensor configurations.

10. PredictionMoments / RemainderStability
    The checked conditional moment and regional remainder bounds require their
    stated regularity, noise and domain assumptions. They do not certify the
    complete delayed switched flight estimator or predict universal flight MSE.

Verification evidence
---------------------

estimator-theory-lean-final.json records ten modules freshly checked from source
under Lean 4.29.1; transitive dependencies use the pinned checked cache. Its kernel
audit covers 1,308 project declarations and permits only Classical.choice,
Quot.sound and propext. No project axiom, admitted theorem, unsafe definition or
unchecked runtime replacement passes the GNC audit. GNC.Core compilation and the
1,392-module structure/export check also pass. This is targeted qualification,
not a complete GNC release verification or hosted CI result.

The covariance-root explicit-copy change additionally fixes an OpenModelica
constant-evaluation discrepancy. The old runtime root matched covariance while
its constant-evaluated root did not. An explicit array comprehension copies the
row before the rotations. A first scalar-loop rewrite was numerically correct
but produced a roughly 46x root-flight CPU regression and was rejected. Its
partial flight evidence is retained in eskf-theory-rejected-scalar-replays.json.
The failing constant test is kept
and now passes; fresh generated-C primitive/correction tests and flight controls
are required too. Compiler-specific behavior is an empirical finding, not a Lean
result. See estimator-theory-validation.json and the comparison CSV for outcomes.

The aggregate assertion run additionally found an unassigned transition matrix
in ESKF.predict, introduced by the earlier covariance-representation refactor.
Nominal packet/sequential motion agreed to roundoff while covariance differed by
0.040001. Restoring transition := discreteTransition(A, dt) fixes the raw fallback;
normal preintegrated replays did not expose it. The existing packet/sequential
regression now passes. An added assertion checks prior-uncertainty retention and
dense/root agreement in the held hover case. A new deployment probe checks 640
zero-noise kinematic cases across correlated priors, time steps including zero,
and both representations. This is numerical qualification of the transition
contract underlying CovariancePropagation.linear_pushforward, not a formal
refinement proof of the Modelica predictor.

Tests.All passes with OpenModelica cflags=-O0. The original default -Os aggregate
build was stopped during a long C compilation, after the partial assembly showed
the Bezier assertion function; no compiler root cause was formally localized.
The successful aggregate is not a completed default-CI pass. Deployment probes
and flight binaries use -O2. The original aggregate failure and raw-prediction
diagnostic are retained alongside the final results.
