Canonical CogniPilot SLAM models
8 October 2026

modelica_models owns the reusable Modelica algorithms. slam_web owns browser
rendering, sensor transport, editing and runtime presentation. It consumes
versioned model snapshots rather than maintaining another authored algorithm.

Package layout
--------------
Vision.Features       FAST/Harris acquisition and bounded feature selection
Vision.Matching       RGB-D descriptors, matching and patch tracking
Vision.Registration   Calibrated robust point registration and its helpers
Vision.Sensors        D435 calibration/depth profile
SLAM                  Public reset, initialize, step and held-IMU entrypoints
SLAM.Localization     Visual observations, registration uncertainty and sessions
SLAM.Inertial         Existing world-additive ES15/Schmidt reference estimator
SLAM.Fusion           Independent visual aiding for the right-injected ESKF
SLAM.Mapping          Anchored landmarks, catalogs and spatial indexing
SLAM.LoopClosure      Keyframes, visual words, retrieval and verification
SLAM.PoseGraph        Measured factors, optimizer, gauge bounds and atomic commit
SLAM.Examples         Application simulation, sensor and evaluation examples
LinearAlgebra         Shared numerical helpers, including the existing SPD6Solve

The flight-navigation ESKF remains Estimation.StrapdownINS.ESKF. The imported
SLAM.Inertial filter has different tangent/injection conventions and remains a
comparison implementation. Moving its source does not silently replace ESKF.
There is no additional ModelicaModels umbrella or vendored library snapshot.

Migration
---------
179 classes from 74 authored files at slam_web revision
99986cac289814d0c4ee0ea5bc8d4519c4560397 were moved into one-class-per-file
Modelica packages. Within clauses and explicit import aliases replace the old
concatenated global namespace. Nested classes and arithmetic are preserved.
docs/slam-source-provenance.json records every original file/class and new
destination. tools/slam/check_migration.py independently checks pinned source
hashes, declaration/arithmetic tokens, alias targets and package inventories.
The old models/Libraries and models/upstream trees were not imported.

The original application checkout can have unrelated work in progress. Consumer
cutover is prepared separately; deleting its current source before the consumer
loads this repository would break the application. Compatibility exports remove
the new package/import wrappers and restore the existing flat model names.
They are generated snapshots; edits belong in these canonical packages.

  python tools/slam/export_legacy_sources.py --revision FULL_COMMIT_SHA \
    --output "$HOME/scratch/modelica_models/slam-browser-snapshot"

This reads committed source only, requires a fresh external output directory,
and emits the existing models/... source paths plus slam-provenance.json.
The export contains no browser implementation or native firmware code.

Local loose/tight qualification
------------------------------
Tests.VisualCouplingReplay executes both paths against the same four RGB-D
observations, complete observation covariance and ESKF prior. Loose compresses
the observations to a six-dimensional pose statistic. Tight uses the raw
pixel/depth residuals. Both correction, SE_2(3) injection and covariance reset
are Modelica functions; C drives the exported entrypoint, and Python supplies
an independent oracle and report.

  python tools/estimator_comparison/qualify_visual.py \
    --rumoca /path/to/rumoca-0.10.2 --cc /path/to/gcc \
    --work "$HOME/scratch/modelica_models/visual-qualification"

Use a fresh directory and Python with NumPy installed. The runner exports the
actual Modelica sources with Rumoca 0.10.2, compiles the exports, hashes sources
and generated artifacts, and runs coordinate, camera-Jacobian and correction
checks. It refuses a source change during qualification.

These first cases assume a FIXED KNOWN MAP and independent new camera noise.
Do not feed uncertain live SLAM landmarks or IMU/GPS-correlated external poses
through these functions as if independent. The retained-map/reference joint
uncertainty implementation, persistent replay and GPS loss/return comparison
remain required before full RGB-D SLAM qualification or a superiority claim.
The imported SLAM full graph likewise retains its prior compiler/runtime
admission limits; relocation alone does not qualify that graph for Rumoca 0.10.2.
